## 2. AAR 解包

`.aar` 不能直接 `Expand-Archive`（它只认 `.zip` 后缀），用：

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
[IO.Compression.ZipFile]::ExtractToDirectory('ffmpeg-kit-full-gpl-6.0-2.aar', 'aar')
```

解包后 `aar/classes.jar` 是 Java 类，`aar/jni/<abi>/*.so` 是原生库，每个 ABI 10 个文件。本工程只打 `arm64-v8a` 与 `armeabi-v7a` 两个 ABI（x86 / x86_64 仅模拟器用，可省）。

**命名注意**：`armeabi-v7a` 的库带 `_neon` 后缀（`libavcodec_neon.so` 等），ffmpeg-kit 的 `NativeLoader` + `libffmpegkit_abidetect.so` 会在运行时自动挑对应名字加载，**不要改名**。

## 3. 编译链

```
aapt2 compile  ->  res 编译成 .flat
aapt2 link     ->  生成 resources.ap_ 与 R.java
javac          ->  src + R.java，classpath 含 android.jar / ffmpeg classes.jar / smart-exception.jar
jar cf         ->  classes.jar
d8             ->  classes.jar + ffmpeg jars -> classes.dex
python pkg.py  ->  把 classes*.dex 与 lib/<abi>/*.so 追加进 apk（so 用 STORED 不压缩）
zipalign -p -f 4  ->  4 字节对齐，且 so 页对齐（-p）
keytool        ->  生成签名库（首次）
apksigner sign ->  签名
apksigner verify  ->  校验
```

关键点：

- `pkg.py` 必须把 `.so` 以 **STORED（不压缩）** 写入，否则 `zipalign -p` 无法做页对齐，运行时 `System.loadLibrary` 会失败。
- `AndroidManifest.xml` 的 `<application>` 必须写 `android:extractNativeLibs="true"`：本包 so 体积大，解压到 lib 目录加载最稳。
- 用 `executeWithArgumentsAsync(String[] ...)` 传参数数组，不要拼一条字符串命令行——省掉路径里空格/引号的转义问题。
- PowerShell 里给 java 传编码参数要带引号：`java "-Dfile.encoding=UTF-8"`。
- `d8.bat` / `apksigner.bat` 跑之前先设 `$env:JAVA_HOME`。
- 用 PowerShell 5 的 `Set-Content` / `WriteAllText` 写含中文的脚本会按 ANSI 读，导致中文路径乱码；构建脚本保持纯 ASCII 输出，中文文件名用 python（UTF-8 源码）拼接。

## 6. FFmpeg 回调的坑

`ffmpeg-kit` 6.0 的三个回调都是 Java 8 函数式接口，抽象方法名是 **`apply`**，不是 `onComplete` / `onLog` / `onStatistics`：

```java
new FFmpegSessionCompleteCallback() { public void apply(FFmpegSession s) {...} }
new LogCallback()                   { public void apply(Log log) {...} }
new StatisticsCallback()            { public void apply(Statistics st) {...} }
```

`Statistics.getTime()` 返回 **毫秒（double）**，算进度时除以「时长毫秒」而不是「时长秒」。
`ReturnCode.isSuccess(...)` / `isCancel(...)` 是静态方法，参数可以为 null。
6.0 没有 `FFmpegKitConfig.init(Context)`，不用初始化；不用 SAF 协议时也不需要 Context。
